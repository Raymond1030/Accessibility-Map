# 移动端适配 — 设计文档

日期：2026-08-12
状态：设计已确认，待实现
前置：`2026-08-12-isochrone-tool-design.md`（已实现并上线）

## 1. 问题

当前布局在窄屏下不可用。实测 390px 宽视口：

- `.sidebar` 是 `width: 300px; flex: none`，`.app-body` 是横向 flex
- 结果：侧栏占据 300px，地图只剩右侧约 90px 的竖条，完全无法使用
- 侧栏内起点列表区 `flex: 1` 但通常没内容，中部大片空白浪费

另有两个触屏特有问题：

- **误触加点代价高**：每加一个起点会立即发起 3 次 `ArrivalRange` 请求（15/30/45 三档）。手机上拖动地图浏览、点击收起面板都可能误触发加点，直接消耗配额
- **触摸目标过小**：chip 按钮 `padding: 3px 8px`，实测高度约 24px，远低于 iOS 人机指南建议的 44px 最小可点尺寸

## 2. 布局机制

### 2.1 单一 DOM，CSS 切换形态

**不做两套 UI。** 侧栏与底部抽屉是同一个组件、同一份 DOM，仅由 CSS 决定形态：桌面端为左侧固定栏，移动端为底部抽屉。

理由：两套 UI 意味着每个功能都要实现两遍，而该应用的控件仍会继续增长。代码分叉的维护成本远高于 CSS 条件的复杂度。

### 2.2 断点

`768px`。宽度小于等于该值时启用移动端形态。

```css
@media (max-width: 768px) {
  .app-body { flex-direction: column; }
  .map-view { position: absolute; inset: 0; }
  .sidebar {
    position: fixed; bottom: 0; width: 100%;
    height: 72vh;                          /* 展开高度 */
    border-radius: 14px 14px 0 0;
    transition: transform .25s ease;
  }
  /* 折叠：整体下移，只留 90px 的把手 + 结果摘要露在屏幕内 */
  .sidebar.collapsed { transform: translateY(calc(72vh - 90px)); }
}
```

展开高度 `72vh` 与折叠露出高度 `90px` 是这套位移的唯一两个输入，改其一必须同步改 `translateY` 的计算式。

### 2.3 抽屉两档

只做两档，**不做三档、不做拖拽手势**：

- **折叠**：只露出把手与一行结果摘要，高度约 90px
- **展开**：占 `72vh`

通过点击把手切换。

拖拽手势需要处理速度阈值、边界回弹、以及与地图平移手势的抢夺，实现与调试成本远高于收益。确有需要再加。

### 2.4 移动端必需的两个细节

- 抽屉内容区设 `overscroll-behavior: contain`，否则内容滚到底会把整个页面一起拽动
- 底部内边距使用 `env(safe-area-inset-bottom)`，否则 iPhone 底部横条会压住按钮

### 2.5 屏幕旋转

高德地图在容器尺寸变化时**不会自动重算**，需在 `resize` 事件中调用 `map.resize()`，否则旋转后地图拉伸变形。

## 3. 状态与加点模式

### 3.1 新增状态

置于现有 store：

```ts
drawerOpen: boolean      // 抽屉展开/折叠
pickingMode: boolean     // 是否处于选点模式
```

### 3.2 加点流程（移动端）

1. 点「＋加点」按钮
2. 抽屉**自动收起**——不收起则看不见地图，无法选点
3. 地图顶部出现提示条：「点击地图选择起点，再点一次取消」
4. 点击地图落点
5. **自动退出**选点模式，抽屉**保持折叠**

第 5 步保持折叠是有意设计：加完点后用户要看的是地图上新出现的等时圈，不是控件。折叠条内的结果摘要足以传达交集变化。

搜索加点后同样自动收起抽屉。统一原则：**任何加点动作之后都让用户看到地图。**

### 3.3 桌面端行为不变

桌面端仍是直接点击地图加点，无选点模式。因此需要区分两端，判断逻辑抽为纯函数：

```ts
export function shouldAddOnMapClick(isMobile: boolean, picking: boolean): boolean {
  return !isMobile || picking
}
```

该函数看似简单到不值得抽出，但写反的后果很具体：要么手机上永远无法加点，要么持续误触消耗配额。它也是本次改动中唯一含分支的逻辑，其余均为 CSS。

`useIsMobile` 基于 `matchMedia('(max-width: 768px)')` 并监听变化（屏幕旋转需要能切换）。它是薄封装，不做单元测试。

### 3.4 触摸目标

移动端下所有可点元素 `min-height: 44px`（iOS 人机指南最小可点尺寸）。桌面端保持现有紧凑尺寸。

## 4. 验证

布局为 CSS，无法有意义地单元测试。

- **单元测试**：`shouldAddOnMapClick` 四个用例，覆盖「桌面/移动」×「选点模式开/关」
- **视觉验证**：在 390×844（iPhone 14）与 768×1024（iPad）两个尺寸下截图确认
  - 地图是否全屏
  - 抽屉折叠/展开两档是否正常
  - 触摸目标是否达到 44px
  - iPhone 底部安全区是否被遮挡

## 5. 明确不做

- 抽屉拖拽手势（只做点击把手切换）
- 抽屉第三档（半开）
- 移动端专属的功能裁剪——功能集与桌面端完全一致
- 桌面端任何行为变化
