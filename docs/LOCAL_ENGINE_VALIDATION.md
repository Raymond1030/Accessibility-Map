## 启停、资源与恢复验证

省级路网加香港公交首次建图约 4–4.5 分钟，单份图缓存约 2.74 GiB。重用缓存一次启动约 18.5 秒。建图期间观察到 Java 工作集约 4 GB，因此最大堆不等于全部进程内存。

实际发现并处理的环境问题：

1. Windows 短路径 TEMP 导致 Java loopback socket 初始化失败：仅为引擎指定项目内临时目录。
2. Windows 强制终止 Java 后 MapDB 报 `Wrong index checksum`：引入 `EngineHost.java`，通过父进程管道 EOF 正常执行关闭钩子。终端输入 `stop` 后真实退出码为 0，日志记录 Jetty 停止，Java 进程消失，随后成功复用图。某些终端的 Ctrl+C 会直接终止整个进程树，因此推荐 `stop`；异常断电等仍需 `--rebuild`。
3. 2 GB 堆在缓存重载后的公交到达查询中出现 OOM：默认改为 3 GB，并将搜索串行化；上述最终查询在 3 GB 下通过。更密集的自备 feed 或其他地区仍应另做容量测试。

失败图由 `--rebuild` 改名保留为 `.previous-*`，未删除。大文件与完整原始日志位于 Git 忽略目录 `engine/.local/`；当前可复用图和查询证据仍保留本机。

## 实施决定与适用范围

1. 保留现有非主分支及用户未提交界面修改，就地集成，不自动提交或推送；代价是后续提交需按文件审查。
2. 三地使用一份广东 PBF；Geofabrik 已包含港澳，避免重叠导入；代价是比小区域示例占用更多资源。
3. 香港 GTFS 缺港铁，广东其他城市与澳门缺已核验完整班次时保持数据缺口；深圳地铁沿用清楚标记的静态估算；这些模式不能声称完整官方时刻覆盖。
4. Node 18 测试用会话内 Web Crypto 兼容开关，未为既有测试改业务代码；该运行时仍需此开关。

地图底图、搜索及原有高德点到点比较仍依赖原配置；本次离线的是已准备数据的路由计算。跨境通关、实时拥堵、临时停运和真实车辆位置不在当前模型内。
