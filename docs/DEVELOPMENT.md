# 开发文档

面向开发者的技术说明。使用说明见根目录 [README](../README.md)。

## 快速开始

```bash
npm install
cp .env.example .env      # 填入 VITE_MAPBOX_TOKEN
npm run dev
```

Token 从 [Mapbox 控制台](https://account.mapbox.com/access-tokens/) 获取（pk. 开头的公开 token）。它会暴露在前端，应在控制台配置 **URL restriction** 限定部署域名。**token 不要写进任何源码文件**——GitHub 推送保护会识别 Mapbox token 并直接拦下提交。

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器 |
| `npm test` | 跑全部单元测试 |
| `npm run typecheck` | 类型检查 |
| `npm run build` | 生产构建（含类型检查） |

## 设计边界

这些不是待办事项，是当前版本的设计决定：

**1. 公共交通按场景使用不同服务。** 地铁等时圈使用本地深圳线网 Dijkstra，公交等时圈停用；地铁 + 骑行保留原有组合引擎。租房通勤使用高德 Transfer 路线规划，公交含地铁与步行接驳；驾车、步行、骑行通勤也使用高德。原有驾车 / 步行 / 骑行等时圈仍由 Mapbox 提供。

**2. 国内首次加载偏慢，标注靠运行时中文化。** 底图与数据都来自 Mapbox（境外服务）。深圳 5G 实测：首次打开约 3.5 秒、751 KB；缓存后约 0.4 秒。地图标注默认英文/拼音，应用在 style 加载后把全部 symbol 图层改为优先取 `name_zh-Hans`——OSM 数据里没有中文名的要素仍会显示原文。国内路网基于 OSM，精度不如高德。

**3. 全栈 WGS-84 标准坐标。** 底图、等时圈、定位、导出的 GeoJSON 全部是 WGS-84。高德搜索和点到点通勤路线在服务边界进行 GCJ-02 ↔ WGS-84 转换。**地名搜索走高德**（Mapbox Geocoding 在国内连「深圳北站」都只能匹配到城市级），高德返回的 GCJ-02 经 `src/geo/coord.ts` 转成 WGS-84 后进入系统。

## 架构

```
src/
├─ providers/          ← 唯一知道 Mapbox 存在的地方
│  ├─ mapbox.ts          调用 Isochrone API
│  ├─ mapboxTransform.ts URL 构造、档位匹配、错误映射
│  ├─ cache.ts           参数指纹缓存 + 在飞请求合并
│  ├─ gate.ts            并发闸门（上限 4）+ 指数退避重试
│  ├─ timeout.ts         请求超时保护
│  └─ index.ts           withCache(withGate(withTimeout(provider)))
├─ mapbox/             ← token
├─ geo/                ← 定位；coord.ts 为后续保留
├─ geometry/           ← 纯函数，不碰网络
│  ├─ ops.ts             交集/并集/差集/归一化/简化
│  └─ result.ts          面积格式化、档位可用性判定
├─ state/
│  ├─ compute.ts         请求矩阵规划、档位运算编排
│  └─ store.ts           zustand
└─ components/         ← 单侧栏/底部抽屉 + 全屏地图
```

### 三个不显眼但关键的设计

**Provider 是唯一的数据源接触面。** 它对外只吐标准 GeoJSON。几何层和 UI 层完全不知道数据来自哪里——这层抽象让本项目从高德整体迁到 Mapbox 时，几何、缓存、闸门、编排一行未改。

**档位必须按 `properties.contour` 匹配，不能靠数组下标。** Mapbox 把 features 按档位从大到小返回，用 index 取会拿 15 分钟的下标得到 45 分钟的范围——面积大三倍且毫无异常迹象。

**运算前 simplify 是正确性前提。** 等时圈顶点数多时连续 `intersect` 会阻塞主线程。以约 10 米容差预简化——等时圈本身精度远粗于 10 米，不损失有效信息。

### 空结果的处理原则

缺数据时绝不用残缺的点集合去算交集。那会得出一个看起来完全正常、实则错误的结果——比三个点的交集少算一个点，面积只会变大，没有任何异常迹象。因此某档任一点数据缺失时，整档标为「数据不全，无法计算」并列出缺哪个点；单点单档请求失败可独立重试，不阻断其余档位。

### 请求量与缓存

请求数是 `点数 × 档位数`。缓存的参数指纹形状决定了三件事：

- 切换交集/并集/差集 → **零请求**（纯几何重算）
- 点拖走再拖回原位 → **零请求**
- 给某点新增一个档位 → **只请求那一档**

例外是「驾车（实时路况）」：它的指纹拼入 10 分钟时间桶——同一时段内仍零请求，跨时段重新获取以反映路况变化。所有请求经过并发闸门（同时最多 4 个）+ 超时保护 + 退避重试。

## 测试

```bash
npm test    # 运行全部单元测试
```

测试集中在几何运算层和 provider 转换层——逻辑密度最高、出错最不显眼的地方。全部是纯函数测试，不碰网络。

UI 组件和 `mapbox.ts` 的网络壳没有单元测试：可测逻辑（URL 构造、档位匹配、错误映射、时间桶）全部在纯函数层覆盖，为地图 SDK 搭 mock 的收益低于成本。

### 一条从高德时代留下的教训

v1 用高德时踩过三个只有真实环境能暴露的坑（回调静默不触发、成功却报 no_data、bounds 结构与文档不符——详见 git 历史中的对应提交）。共同教训是：**自己造的 fixture 测不出对接口的错误假设**。因此本版的 `pickContour` fixture 直接取自 Mapbox 真实响应，且超时保护（`withTimeout` 在闸门内层）作为通用防线保留——任何数据源都可能挂死。

## 租房通勤的高德接入

- 复用 `src/amap/loader.ts` 的 JS API 2.0 加载器，加载 `AMap.Transfer`、`AMap.Driving`、`AMap.Walking`、`AMap.Riding`。
- `.env` 填写 `VITE_AMAP_KEY`（Web 端 JS API 类型）。本地沿用 `VITE_AMAP_SECURITY_CODE`；公开部署推荐配置 `VITE_AMAP_SERVICE_HOST` 安全代理。变量不要写入源码，API Key 的域名白名单需要包含部署域名。
- 地图仍使用 Mapbox，需要 `VITE_MAPBOX_TOKEN`。接入高德路线不等于移除了 Mapbox 底图依赖。
- `src/commute/amap.ts` 将住处和公司从 WGS-84 转换成 GCJ-02 查询，并将轨迹转换回 WGS-84。公交分别传入居住和工作城市，以最快策略请求，选择返回方案中有效耗时最短者。
- `src/commute/store.ts` 手动触发批量计算，最多 24 次请求、同一批次最多 2 个在飞请求；每次请求包含 SDK 加载的 15 秒超时。修改公司或城市会作废旧批次并停止继续发出旧任务。删除住处不会被迟到结果重新写回。
- 租金、预算、时间上限、排序和方式切换都在已有结果上计算。重新计算会请求新结果，不使用持久缓存。无路线、请求错误、尚未查询分别展示；有限预算下，未知租金不视为符合条件。
- 当前不支持指定早高峰出发时间，不根据从公司向外的等时圈推断逆向上班可达性，不生成缺少的轨迹或票价。候选住处和结果只存于内存。
- 单元测试覆盖响应解析、坐标转换、路线方向、超时、部分失败、筛选边界以及过期结果隔离。真实服务仍依赖有效 Key、配额、域名白名单与高德覆盖范围。

API 依据：[高德 JS API 2.0 公交示例](https://lbs.amap.com/demo/javascript-api-v2/example/bus-search/bus-custom)、[路径规划参考手册](https://lbs.amap.com/api/javascript-api/reference/route-search)。

### 公交 / 地铁线路展示

`Route.transitLegs` 保留高德每段的线路名称、上下车站、站点坐标、途经站数及轨迹。`TransitItinerary` 显示乘车顺序和各段信息；同段 `lines` 中的多个线路作为备选展示，不增加换乘数。`commute/transit.ts` 输出地图分段实线、步行虚线和站点标注的数据，面板与地图复用配色；缺少名称或轨迹会明确提示，不补造站点或连接线。

### 无候选住处的工作地通勤圈

`CommutePanel` 默认展示 `view=range`，仅需要工作地。`WorkplaceRange` 选择地铁（`subway-walking`）、驾车、骑行或步行和 1–60 分钟，复用已有 provider 的缓存、限流及超时。`evaluateRange` 的请求代次独立于住处比较，修改工作地、方式或时长使在飞结果作废。两个视图保留各自数据，地图只显示当前视图的范围或路线。

地铁使用 `providers/metroWalking.ts`，租房场景传入 `direction=arrive`，多点场景默认 `depart`。`metroArrivalCosts` 反转有向邻接边，在终点站以“出站 + 到公司步行”初始化，求解后为每个起点加进站和该线路候车成本；反转时保留原边权，不能把换乘目标线的班距换错。

两端接驳上限均为 15 分钟。终点步行时间按 2/5/8/10/12/15 分钟轮廓向上取档（预算不足时加入实际分钟）；起点剩余时间向下取整至整数分钟。步行轮廓仍来自 Mapbox，假设步行通行方向对称，故到达范围是模型估算。直达步行区也纳入。各站路网多边形直接 union，不画凸包或圆形缓冲，不按距离抽稀车站，保留不连通区域。Mapbox 参数见 [官方文档](https://docs.mapbox.com/api/navigation/isochrone/)。

腿级请求共享缓存、超时和闸门，车站队列最多 4 个并发；整体不设 10 秒超时，不缓存可取消的地铁总请求。修改条件会取消旧队列、忽略旧进度与结果；已经发出的共享腿请求允许完成并进入缓存。任一车站路网缺失/失败则整体报错，避免残缺圈冒充完整结果。

`geometry.properties.metro` 记录方向、线网日期、可接驳车站及剩余步行预算。地图圆点/站名和虚线来自 `transit/mapFeatures.ts`，虚线仅为站间拓扑，不能宣称轨道轨迹。OSM/ODbL 线网仅覆盖深圳，2/8 贯通线路去重；静态快照中 13 号线北延段缺失，界面必须保留覆盖提示。区间运行时间按站距/35km/h + 0.75 分钟停站估算，默认进出站各 2 分钟、班距 5 分钟、换乘走行 4 分钟，无首末班车/实时列车数据。

驾车、骑行、步行仍是 Mapbox 的**从工作地出发**范围。公交 ArrivalRange 未注册、未加载；旧响应解析文件仅保留作历史兼容测试。

测试覆盖无候选住处生成、四种方式分发、过期结果隔离、无覆盖/错误区分与重试、视图切换保留数据。此模式不查询房源、不发送点到点通勤请求。

地铁颜色统一由 `src/transit/lineColors.ts` 提供，核对来源为[深圳地铁官网线路页面](https://www.szmc.net/map/)及其 `styles/index/css/all.css` 的 `.lineN .xl_name_c`。地图线路、单线车站、标签和面板图例共用同一映射；换乘站使用中性描边。高德点到点路线仅在确认起终城市均为深圳且该段为地铁时套用此映射，未知城市/线路保留备用色。


## 生活探索与搬家比较

- `src/state/navigation.ts` 统一管理三个应用场景及选点退出；`src/explore/` 提供 POI、评分、盲盒、内存查询队列和探索状态；租房对比通过 `src/commute/comparisonStore.ts` 复用有向路线服务。保留当前地铁通勤圈实现。
- POI 使用高德 JS API `PlaceSearch`，分类码集中配置，来自[官方分类表](https://lbs.amap.com/api/javascript-api/download)。每类最多 3 页 × 20 条，按 ID 去重并在 WGS-84 中做包含孔洞的范围过滤；画像按直线距离选前 5 个进行真实路线核验。不能把搜索结果总数当作可达场所总数。
- 公交到达圈服务已停用，生活探索公交模式使用 `searchNearBy`（50 公里、限制所选城市）发现候选，再调用 Transfer 核验。步行、骑行、驾车复用现有等时圈并调用 `searchInBounds` 检索。
- 新增范围、POI 和路线请求共用并发 2 的队列，开始请求至少间隔 1.1 秒；QPS 错误最多退避重试两次。执行请求超时 15 秒，成功结果缓存 10 分钟，仅内存保存。方向、城市、出行方式参与缓存键；参数变化取消排队任务并隔离迟到结果。
- 分类分为 `100 × (0.5 × min(n/3,1) + 0.5 × max(0,1-t/T))`，其中 n 为样本中核验可达的数量，t 为最短耗时，T 为上限；无可达结果为 0。错误或未查询的加权类别使总分暂不可用；零权重不参与。
- 月通勤时间使用去程加回程乘通勤天数。每周出行时间使用各目的地的双向耗时乘往返次数。缺任一方向不生成完整节省结论，但每周合计保留已完成方向并列明缺失去程／回程；租金、天数和权重只影响本地计算。
- 搬家配套差异取两处已核验 POI 的并集，并补查另一住处的路线；只有双侧可达性已核验才归入共同、新增或不再可达，避免把检索遗漏误当作不可达。交叉核验失败时保留完成部分并提示补查。
- 盲盒随机打乱去重候选，每次最多核验 12 个、接受最多 3 个，只有 `seconds <= minutes * 60` 才可入选。记录按起点、城市、方式、时间、类别分组，收藏及排除项在本次页面会话内生效。
- 测试覆盖分类解析、分页/去重/孔洞、四种方式分发、评分缺失语义、限流/超时/缓存、双向租金比较、频次、盲盒以及过期请求隔离。真实验证需有效 Key、域名白名单和服务配额。
